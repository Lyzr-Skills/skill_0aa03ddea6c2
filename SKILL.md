# Florida material risk — latency-first, exact-coverage workflow

## Contract
- Sources: only the bound Anaplan model `PMGT - Inventory Planning V6.0` and, **for a finished-goods follow-up only**, the user-supplied full Excel BOM. Read-only: do not write cells, run imports/processes, or create orders/transfers.
- Within this conversation honor the user's confirmed **Florida DC, Scenario 1, next 26 model weeks** unless changed. In other conversations follow the explicit location/horizon/scenario; if location/horizon absent scan all locations/full forecast and say so. If scenario ambiguous, ask rather than mix scenarios.
- Start with material risks; do not read the BOM for a material-only request. On a re-run, re-read all numerical data; do not copy previous values or assume previous SYS003 period still holds.

## Minimal setup (do not browse the model)
1. `get_model_context`. If not bound to the exact model, `catalog_models(name_contains="PMGT - Inventory Planning V6.0")` and `set_model_context`. Bind only once. Use cached schema from THIS model when verified. Otherwise `catalog_modules(name_contains="IEO200")` and `catalog_modules(name_contains="SYS003")`, then `catalog_line_items` and `sql_schema` only for selected measures. Exact modules: `IEO200 - Inventory EO by DC`; `SYS003 - Current Period`. Do not rediscover all modules or call `list_time_anchors` for the final answer: its native calendar may disagree with SYS003 and its scan may be slow.
2. Always `read_cells(module="SYS003 - Current Period", line_items=["EF Current Period"], slice={}, leaf_dimensions=[], limit=1)` **on this run**. This is the effective clock (formula may use manual current period or today). If unreadable, stop and report. NEVER use the native FY25 calendar or an old Week 1 FY25 observation in place of a fresh SYS003 read. For “next 26 weeks” include the current SYS003 week plus 25 following model weeks. Optionally `set_time_anchor` with the fresh period (`source="custom_module"`, `module="SYS003 - Current Period"`, `line_item="EF Current Period"`, `confirmed_by_user=true`) only if a relative-time tool is needed.
3. Use the IEO200 native weekly Time dimension to obtain 26 **actual consecutive** model week labels, in model order. On a cold session use `sql_schema` on IEO200 and query the Time list table if available, or use `resolve_time_window`/time metadata as appropriate; never generate labels by incrementing strings, and do not silently take an FY25 or quarter summary as the 26-week window. If calendar does not provide 26 weeks, use only available periods and disclose. Identify actual dimension names via `sql_schema` (known module dimensions: `HLP080:PROD_ISPlanned`, `HLL080:LOC_ISDC`, `SCL100 - DC Inventory Scenarios #`, `Time`). Pin the location to the confirmed Florida member, scenario to confirmed Scenario 1. This is a scenario list, not a native version.

## ONE primary data read shape; no 26-query default
4. Prefer **one sparse, two-leaf-axis `read_cells` request**, then page: `module="IEO200 - Inventory EO by DC"`, `line_items=["Shortfall (U)"]`, `slice={"HLL080:LOC_ISDC": "Florida", "SCL100 - DC Inventory Scenarios #": "Scenario 1"}` **only after verifying member labels from metadata/schema**, `leaf_dimensions=["HLP080:PROD_ISPlanned", "Time"]`, `limit=500`, `skip=0`. Follow `pagination.next_skip` until `has_more=false`; retain only rows whose `time` is one of the 26 verified weeks, and only negative shortfalls. This reads sparse populated rows across the module's available time, so check page count and wall time: one request may still time out. DO NOT read only the first page and claim full coverage; DO NOT apply a two-leaf measure filter in SQL (rejected and may scan a huge grid). A blank cell is not automatically a negative shortfall.
5. If the two-axis read errors or repeatedly times out, **do not retry the same expensive request**. Fallback to individual weekly reads with `read_cells`, fixing week, Florida and scenario, leaving only product leaf, `limit=500`, exhausting every page; read weeks sequentially or in batches of at most two. If the model has a safe precomputed 26-week shortlist/filter, use it only when its logic is verified against SYS003 and the 26-week window. Stop after one failed broad read and one failed bounded week, and say exactly which weeks were verified; do not let a tool loop time out. An all-period `Shortfall (U) NoTime` total is NOT a 26-week filter and may hide negative weeks through cancellation.
6. Define “significant” explicitly from what the user supplies (e.g., material units or % demand). If none, show the largest absolute negative `Shortfall (U)` values with first week, number of negative weeks, and label them **largest observed**, not objectively significant. Do not add weekly shortfall amounts as an order quantity; carry-forward unmet demand may recur. For true inventory-based stockouts, read forecast ending inventory and safety stock if verified and available; `Shortfall (U)` alone measures unmet demand, NOT available inventory or safety-stock breach. If only shortfall was checked, state that inventory/safety stock were not assessed.
7. Mark completion ONLY after all pages and every intended week were examined. If a read fails, show partial results separately, with the exact uncovered weeks, and never say “none” for uncovered data. A re-run must return newly read cells, or explain why it could not.

## If user subsequently asks about finished goods
- Use the already verified period/product shortfall rows, refreshing them if the data has changed. Access the **entire current user-provided Excel BOM**. If unavailable, stop and request the workbook; old reports or a partial PDF search extract do not establish the complete BOM.
- Match material identifiers exactly, using Anaplan codes or verified part-number mappings. Exclude and list unmatched material codes; do not infer equivalence from similar names. Recursively explode parent-child paths with configured quantities, detect cycles, avoid double counting, treat zero-base optional parts as conditional, and never assume Synergy frames contain particular blades without documented parent links.
- Severity: Critical for risk in weeks 1–4 or verified zero buildability; High weeks 5–8; Medium after week 8 or safety-stock-only. For each finished good give earliest matched-risk week, all simultaneous flagged components, location, component gap, and capacity only when actual usable unallocated inventory and planned builds exist: `max buildable = min(floor(max(0, usable inventory)/qty per FG))`; `unbuildable = max(0, planned builds - max buildable)`. Otherwise `not determinable`. Material unmet demand is not FG units unbuildable and does not prove the capacity bottleneck.
- Recommend for Critical/High: first check feasible transfers from uncommitted surplus, then open-PO expedite, then new PO if verified lead time permits; approved substitution only if documented; if impossible, prioritize unaffected builds and flag delivery impact. Name material, provisional quantity, Florida DC and required model week in each action; qualify unverified availability or timing. Ask planner for priorities if one component feeds multiple FGs. Never imply an action was executed.

## Output and practical timeout escalation
- Material-only: first-week shortages and magnitude, ordered by first week then size; SYS003 effective week, first/last of 26 verified weeks, scenario/location, complete vs partial scan, read date, and meaning of the shortfall measure. Follow-up FG: one-line counts by severity; sorted severity/earliest-period table; recommendations; unmatched/optional items; missing buildability inputs and any partial coverage.
- If the two-axis sparse read still times out, **a skill cannot make this backend query faster**. Recommend that the Anaplan owner supply a read-only 26-week SYS003-anchored exception report/export or a precomputed filtered module with material, location, scenario, first negative week and minimum weekly shortfall. Such a model change is for the owner, never perform it under this read-only skill. Don't claim a performance benchmark without a timed run.
